# 验证标准

## 适用范围

业务代码交付执行 pytest、mypy --strict、ruff check；不允许以空测试集合或忽略错误代替通过。
工具、测试及入口的当前可用性见 PROGRESS.md；缺失属于业务验证阻塞。

## 验证顺序

1. 单元：验证受影响逻辑，包含错误输入和安全边界。
2. 集成：单元层通过后，验证 API 与模块协作、认证和权限拒绝路径。
3. 端到端：集成层通过后，启动真实服务，通过 HTTP 验证声明的业务结果。

模拟依赖只证明对应范围的行为；启动成功或 HTTP 200 不证明真实检索或模型生成成功。
检查流程应遇错停止，并记录各层命令、退出码和测试数量。统一入口的实现状态见 PROGRESS.md。

## 文档变更

纯文档变更核对本地链接、入口、路由、依赖、命令、代码块和事实。业务测试可记录“不适用”，同时说明未修改业务代码。
对业务代码变更，缺工具、缺依赖或缺测试不得记录为“不适用”。
纯文档任务的三层业务测试统一记“不适用：未改业务代码”；项目运行基线另列，不能将两者混在一起。

## 证据与复验

进度记录日期、命令、结果、适用范围、失败原因和下一步。已有基线失败单独记录。
已经通过的检查，仅在新修改或疑点可能使结果失效时重跑。

## 文档交付记录

记录实际命令或可复验检查步骤、日期、结果和范围，不必粘贴完整日志。
README 同步记录格式：触发变化、对应段落、核对依据与结果；不影响使用说明时写明理由。
自动检查只能辅助验证路由、链接等结构事实，不能代替语义核对。
